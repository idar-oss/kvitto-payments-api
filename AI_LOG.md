# AI_LOG

## Инструменты и модели

Для выполнения тестового задания использовал ChatGPT (GPT-5.6 Sol) как помощника при разборе требований, проектировании структуры FastAPI-приложения, подготовке SQLAlchemy/Pydantic-моделей, тестов и документации. Код и запуск приложения проверял локально в VS Code с PostgreSQL через pgAdmin 4.

## Ключевые запросы к ассистенту

1. «Ознакомься с тестовым заданием и составь план реализации. Учти деньги только в копейках, промокод, рассрочку, Idempotency-Key и допустимые переходы статусов».
2. «Собери минимальный рабочий проект FastAPI под PostgreSQL по требованиям задания: модели, схемы, эндпоинты, бизнес-логику и pytest-тесты, без необязательных бонусов».
3. «Помоги проверить проект перед сдачей: запуск, подключение PostgreSQL, Swagger, тесты, README и AI_LOG.md».

## Где ИИ ошибся или предложил слабое решение

В начале ассистент предложил SQLite как более простой вариант. По условиям задания это допустимо, но для моего окружения удобнее PostgreSQL, так как я уже работаю с pgAdmin 4. Поэтому рабочее приложение было настроено на PostgreSQL, а SQLite оставлен только для изолированных автоматических тестов.

При проверке подключения ассистент сначала предложил команду с импортом `engine` из `app.database`. В проекте такой переменной не было — используется функция `get_engine()`, поэтому появился `ImportError`. После проверки файла `database.py` команда была исправлена на вызов `get_engine()`.

Также в первой версии README имя базы было указано как `kvitto`, хотя локально была создана база `kvitto_db`. Перед сдачей документацию сверил с реальной конфигурацией и исправил имя базы.

Отдельно проверял критичную денежную логику: суммы хранятся целыми числами в копейках, `float` не используется, а график рассрочки распределяет остаток по первым платежам так, чтобы сумма графика всегда точно совпадала с суммой платежа.
